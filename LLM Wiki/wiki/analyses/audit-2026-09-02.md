# Сверка 2026-09-02: issue и вики против кода

Полный проход по 64 открытым issue и 33 страницам вики, каждое утверждение проверено
открытием файла на `dev` @ 45a2c09. Повод: за 1 сентября в код ушло больше, чем вики и
трекер успели заметить — удаление Family Manager из платформы (63a1992), `ui.buttons` и
версия схемы, три окна вместо одного Settings, форма редактирования манифеста, стопки
через границы расширений.

## Семь выводов

**1. Тесты на `dev` не существуют.** Roadmap (этап 1, пункт 2) и #128 говорят «проекты
`AnalyseTool.Core.Tests` и `AnalyseTool.Tools.Tests` уже есть и просто не запускаются».
На `dev` их нет: `git ls-files src/AnalyseTool.*.Tests` пуст, на диске только сиротские
`bin/obj`, в `AnalyseTool.sln` один `AnalyseTool.Test` (NUnit + Revit-ссылка на App).
Проекты живут только на ветке `claude/pipelines-plan-f8jrgf` вместе с целью `RunTests`
(b1ac574). Пункт «включить прогон тестов в CI — часы» на самом деле «перенести проекты с
ветки, потом включить».

**2. Ветка конвейеров тихо гниёт — и это единственное место, где есть код #88–#92 и #128.**
64 коммита вперёд, 83 позади, разошлась 2026-07-30, последний коммит 2026-08-05.
Реализованы все три этапа, включая нодовый редактор #91 — гейт «строить только по
запросу» не соблюдён. `PipelineSafety` называет `Purge*`, которых в платформе больше нет.
Решение нужно одно из двух: rebase и слияние по частям (сначала тесты + `RunTests` +
`FailureHandling`, они полезны при нуле конвейеров), или закрыть #91/#92 как «построено на
ветке, гейт возвращён» и выдёргивать оттуда точечно.

**3. Четыре блокера витрины не тронуты.** #120 называет #97, #98, #100, #102 условиями
выхода бесплатной части. Ни один не получил коммита с 2026-08-13; последний день ушёл в
интерфейс. #97 по-прежнему одна строка (`McpBridgeServer.cs:274-277`: `ex.Message`, без
`InnerException`, без лога) и по-прежнему первый: без него #98 и #104 — угадайка. Порядок
этапа 1 в [`roadmap.md`](roadmap.md) остаётся верным, меняется только пункт 2 (см. вывод 1).

**4. Вопрос-гейт ветки MCP отвечен, полчаса как обещано.** `ModelContextProtocol 1.3.0`
(`Directory.Packages.props:42`) ссылается на ревизии 2024-11-05 … 2025-11-25 и **ни на
одну 2026 года**: `requestState`, `ttlMs`, `cacheScope` из `2026-07-28` отсутствуют. Но
уже есть `tasks/get|cancel|list|result`, `McpTaskStatus.InputRequired`,
`ElicitRequestParams`, `ImageContentBlock`, `ToolListChangedNotification`. Значит на уровне
API разблокированы #100 (list_changed), #108–#110 (прогресс, отмена, Tasks) и форма
elicitation для #106; заблокированным остаётся только то, что буквально требует
`2026-07-28` (#107 ttl/cacheScope, #111).

**5. Удаление Family Manager не разнесено по трекеру и вики.** Семнадцать команд ушли в
расширение, и за ними: #45 и #114 теперь про другой репозиторий; #83, #88, #106 называют
первыми целями команды, которых в платформе нет; шесть страниц вики и `AGENTS.md` всё ещё
перечисляют слайс `Families/` или приводят `GetFamilies`/`PurgeFamilies` как платформенные
примеры. Урок для вики: крупное удаление из платформы — это событие для ingest, не только
для changelog.

**6. Версия схемы манифеста отгружена наполовину.** Поле `schema` есть
(`ExtensionManifest.cs:17`), #127 закрыт — но ни `GetExtensionDiagnostics`, ни
`GetInstalledExtensions`, ни окно Extensions его не показывают, и в `LLM.md` нет раздела
миграции. Смысл [`contract-evolution.md`](../concepts/contract-evolution.md) был в
*сигнале*, а не в поле. Остаток стоит записать явно, иначе он потеряется за закрытым issue.
Попутно: правило «незнакомые ключи переживают запись» выполнено, но не через
`[JsonExtensionData]`, а тем, что `ExtensionManifestWriter` правит разобранный `JObject`.

**7. Трекер и вики отстают от кода на один рабочий день — и это норма, которую надо
обслуживать.** Семь issue можно закрыть, десять сузить, двадцать утверждений вики устарели
(в основном номера строк, счётчики и примеры на семействах). Ничего из этого линт не видит:
ссылки целы, файлы на месте, устарели *утверждения*. Единственный работающий детектор —
такой проход; стоит делать его после каждого дня с удалениями или переименованиями.
