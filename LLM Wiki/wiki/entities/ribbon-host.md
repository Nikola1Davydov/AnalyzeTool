# RibbonHost — лента AnalyseTool

Лента плагина в Revit: одна большая кнопка, блок Manage из шести маленьких и кнопки
расширений, собранные из манифестов. Код — `src/AnalyseTool.App/Common/Extensions/RibbonHost.cs`;
Launcher зовёт `Build` через рефлексию по имени типа, поэтому переименование класса требует
правки строк в `Launcher/App.cs` (см. `CLAUDE.md` репозитория).

## Как выглядит сейчас

Вкладка `AnalyseTool`, две панели (сверено с `Build` 2026-09-02):

| Панель | Что в ней |
| --- | --- |
| Parameter | одна большая кнопка — сам инструмент (`AnalyseToolMain`) |
| Manage | две колонки по три через `AddStackedItems`: слева **Scripts · Settings · Report a bug**, справа **Reload · Extensions · New** |

Разделение колонок — по работе, не по размеру (комментарий в `Build`): левая — то, чем
пользуются каждый день (скрипты, настройки, обратная связь), правая — жизненный цикл
расширения (перезагрузить, управлять, создать). До 2026-09-01 (bdd3fa4) менеджер расширений
жил внутри Settings — «менеджер, в который ходят работать, спрятанный под страницей,
которую настраивают один раз».

Переключаемых кнопок только две — главная и Scripts (`_staticButtons`; команды
`GetHostButtons` / `SetHostButtonVisible` в `src/AnalyseTool.App/Features/HostButtonCommands.cs`,
обе `HiddenFromMcp`). Остальной блок Manage не выключается сознательно: Settings обязан
оставаться достижимым, и Reload вместе с ним.

## Три системных окна

Settings, Extensions и New — один класс `SystemWindow`
(`src/AnalyseTool.App/Common/Extensions/SystemWindow.cs`) и три маршрута clientapp:
`#/system/settings`, `#/system/extensions`, `#/system/new-extension`. Отличаются маршрутом,
заголовком и размером, больше ничем; одно окно на ключ, второй клик фокусирует открытое.

Почему три, а не одно: **Settings — предпочтения, которые ставят один раз; Extensions —
менеджер, в который приходят работать; New — форма, которая закрывает себя сама**
(`window.close()` из страницы → `WindowCloseRequested` → `Close()`). Смешать их — значит
спрятать рабочее место под страницей настроек, а форму — за списком всего остального.

Scripts — не окно, а док-панель: `ShowScriptLauncher` показывает маршрут `#/scripts` в
единственной зарегистрированной панели `DockPaneHost`. Revit разрешает регистрировать панели
только на старте, поэтому панель одна, а содержимое подменяется маршрутом — так же
показываются `dockable`-кнопки расширений.

## Кнопки расширений и `PackStacks`

Кнопки из манифестов строятся через AdWindows, ключ — «id расширения + индекс кнопки»:
переименование оставляет кнопку на месте, двигает только перестановка. Формы кнопок —
`push`, `pulldown`, `stacked` — описаны в [`extension-manifest.md`](extension-manifest.md);
идущие подряд `stacked` образуют одну серию.

Маленькие кнопки не размещаются при сборке: `PackStacks` раскладывает их **по панели**,
колонками по три — той же формы, что делает `AddStackedItems`, — независимо от того, из
какого расширения пришла каждая. Порядок внутри панели: `order` кнопки → id расширения →
порядок объявления; колонки идут после крупных элементов панели. Пересобирается с нуля на
каждом refresh, поэтому удаление тривиально.

С 2026-09-02 тот же проход сортирует и **крупные** кнопки панели, а `order` входит в
сигнатуру кнопки (иначе смена порядка не перестраивала ничего — первая жалоба на форму
редактирования). Правило ранга: меньше — раньше, **0 (не задан) — после всех заданных**:
человек, вписавший 1 в одну кнопку, ждёт её первой, а не позади всех, кто промолчал
(`RibbonHost.Rank`; то же правило в `EffectiveButtons()` внутри одного манифеста).

Формулировка из комментария кода, которую стоит запомнить: **кнопка принадлежит
расширению, колонка — панели.** Пользователь, пометивший по одной кнопке маленькой в двух
расширениях, ждёт их друг под другом, а манифест ни одного из них не может этого сказать.

Отдельно живут пины — кнопки команд, которые пользователь закрепил из лаунчера
(`_pinnedButtons`, команда `SetCommandButton`): они именуют команду, а не расширение, и могут
указывать на команду расширения, чей манифест писать нельзя.

## Несобранная DLL прячет не всё

С 2026-09-02 расширение, чья `entryAssembly` не собрана для этого года Revit, **не исчезает**
с ленты: кнопки, открывающие страницу, показываются (странице DLL не нужна), скрыты только
кнопки с `command` — они звали бы команду, которая не загрузилась. Повод: шаблон «страница +
C#» сразу после создания выглядел как «создал — и ничего не появилось».
`RibbonHost.RefreshExtensionButtons` (фильтр `IsCompatibleWithHost || OpensPage`) и
`GroupButtons` (отсев командных кнопок).
