# AnalyseTool 2.0 — переписывание на шаблоне

> Статус: этапы 0–6 выполнены; 2.0.0 выпущена 2026-11-16 (тег `2.0.0`), на `rewrite` идёт 2.0.1. Что дальше — раздел 7a. Решения — в разделе «Решения», несделанный выбор — в «Открытых вопросах».

## 1. Цель

Начать AnalyseTool заново на [Davydov.Revit.Template](https://github.com/Nikola1Davydov/Davydov.Revit.Template)
(`dotnet new davydov-revit`), сохранив суть: платформу команд с WebView2-интерфейсом, MCP для агентов и публичный Sdk
для сторонних расширений. Встроенная функциональность 1.x (Elements, Actions, SharedParameters, управление
расширениями, ExecuteRevitCode) переезжает целиком.

Главное новое:

* **Кнопки по умолчанию — исходники `.cs`**, а не DLL. Roslyn компилирует их внутри Revit. DLL по-прежнему читаются.
* **У каждой кнопки своя git-история**, и пользователь управляет ею в интерфейсе: какая версия активна, история,
  diff, откат.

## 2. Решения

1. Переписываем AnalyseTool в его же репозитории, версия 2.0. BimAnvil ушёл в Пижамку; AnalyseTool не замораживается.
2. Основа — шаблон `davydov-revit`: Launcher с изоляцией в ALC, Generic Host, конвейер команд с middleware,
   `IRevitDispatcher`, WebView2, MCP по HTTP внутри Revit, ModularPipelines, WixSharp, TUnit.
3. Публичный `AnalyseTool.Sdk` остаётся (`IRevitTask`, `IRevitContext`, `RevitPayload`, `[RevitCommand]`). Это
   контракт и для `.cs`-кнопок, и для DLL-расширений 1.x. Адаптер встраивает `IRevitTask` в конвейер шаблона.
4. **`.cs` по умолчанию.** «Новая кнопка» (UI и MCP) создаёт исходник. Причины: осмысленный git-diff, один исходник на
   все версии Revit, не нужны Visual Studio и SDK, прозрачность кода, горячая перезагрузка.
5. **DLL — полноправный вариант** для поставки: закрытый код, тяжёлые NuGet-зависимости, авторы на Sdk из NuGet.
   Загрузка как в 1.x (collectible ALC, общая идентичность типов Sdk).
6. **Одна кнопка — одна папка — один git-репозиторий.**
7. **Фронтенд — React** из шаблона. Страницы Vue из 1.x переписываются.
8. Git — LibGit2Sharp в процессе Revit, порт `IProjectHistory` из `Pijamka.Revit.Projects`. Пользователь видит слова
   «версия», «сохранить», «восстановить», а не commit и branch.
9. **Лента, как в 1.x:** новая кнопка появляется на ленте сразу, удалённая скрывается (Revit не удаляет кнопки на
   ходу), окончательно исчезает после перезапуска.
10. Всё локально и бесплатно: без сервера, аккаунтов и лицензий. Обмен кнопками — через папки или git remote.

## 4. Модель кнопки

```
%LOCALAPPDATA%\AnalyseTool\buttons\<id>\
  .git\
  .gitignore         bin\, obj\, *.csproj, созданный для редактора
  button.json        id, имя, иконка, подсказка, панель, порядок, kind: source | dll, активная версия
  src\*.cs           исходники (kind: source)
  lib\*.dll          необязательные сторонние сборки, на которые ссылается компиляция
  <year>\*.dll       сборка (kind: dll)
  icon.png
  ui\                необязательная страница
  bin\<year>\        кеш компиляции
```

### Жизненный цикл `.cs`-кнопки

1. **Создание** (UI или MCP `create_button`): папка, `button.json`, `src\Hello.cs`, `git init`, первая версия.
2. **Загрузка:** поиск классов с `[RevitCommand]` через Roslyn (работает и с ошибками: кнопка не пропадает, пока код
   чинят). Компиляция против Revit API запущенной версии, Sdk и `lib\`. Кеш по хешу исходников, ссылок и версии
   Revit — при неизменном коде старт ничего не стоит. Компиляция в фоне после старта Revit, не на его пути.
3. **Изменение:** FileSystemWatcher, затем пересборка и замена collectible ALC. Ошибки компиляции видны в интерфейсе,
   кнопка неактивна и показывает ошибку.
4. **Запуск:** через конвейер шаблона, как любая команда (лог, активный документ, отмена, прогресс).
5. **Редактор:** по запросу создаётся `.csproj` с IntelliSense (шаблон из 1.x, `Features/Extensions/Templates`). Он не
   попадает в git. PDB со встроенным исходником — для отладки через подключение к Revit.

### DLL-кнопка

`kind: dll`, сборка в `<year>\`. Git версионирует бинарник: история и откат есть, diff нет. Расширения из
`%LOCALAPPDATA%\AnalyseTool\extensions\` в 1.x открываются как есть.

## 5. Версии в интерфейсе

Для каждой кнопки:

* **Статус** — «есть несохранённые изменения» или «сохранено», со списком изменённых файлов.
* **Сохранить версию** — с комментарием; автор — пользователь Windows.
* **История** — версии, новые сверху, кто и когда; фильтр по файлу.
* **Diff** — между версиями и между версией и текущими файлами (Monaco diff editor).
* **Восстановить** — всю кнопку или один файл. Несохранённое сначала сохраняется версией, восстановленное становится
  новой версией: ничего не теряется, история только растёт.
* **Активная версия** — кнопку можно закрепить на версии. Тогда компилируется дерево этого коммита, а не рабочие
  файлы. Видно в списке кнопок; «Открепить» возвращает к текущим файлам.
* **Позже:** клонировать кнопку из удалённого репо или папки, подтянуть обновления, отправить свои.

Те же действия доступны агенту через MCP: `list_buttons`, `create_button`, `read_file`, `write_file`, `build_button`,
`run_button`, `button_status`, `save_version`, `history`, `diff`, `restore`, `pin_version`.

## 7. Риски

* **LibGit2Sharp в ALC** — нативная `git2-*.dll` должна найтись из изолированного контекста. В Pijamka это уже
  решено; если не выйдет, реализация `IProjectHistory` поверх `git.exe` подставляется без изменений вокруг.
* **Время старта** — компиляция многих кнопок. Смягчается кешем и фоновой компиляцией; замерить бенчмарком на 50 кнопках.
* **Совместимость Sdk** — DLL 1.x должны грузиться без пересборки. Тест: `samples/Acme.Sample` из 1.x в 2.0.
* **Объём переноса UI** — все страницы Vue переписываются на React; переносить по слайсам вместе с этапом 1.

    организацией». Команды и MCP тоже соблюдают: `SetMcpEnabled`, `SetScriptingEnabled` и т. п. отвечают кодом
    `managed_by_policy`, не меняя значения. `GetPolicy` — для страниц: какие ключи заданы и откуда.
  - **Когда действует.** При старте и без перезапуска Revit: перечитать при изменении ключа (`RegNotifyChangeKeyValue`) или
    при открытии панели — `gpupdate` доходит сам.
  - **Первый набор ключей:**

    | Ключ | Что значит |
    |---|---|
    | `McpEnabled`, `McpPort` | AI-клиенты могут подключаться к Revit; на каком порту |
    | `ExecuteCodeAllowed` | AI может выполнять произвольный C# (`ExecuteCode`, `DescribeApi`) |
    | `UserExtensionsAllowed` | пользователь может создавать свои кнопки и наборы тестов |
    | `ExtensionRoots` (список, у каждого `readOnly`) | папки компании с кнопками и тестами, например `\\server\AnalyseTool` |
    | `PackagesAllowed`, `PackageSources` | установка пакетов и откуда можно |
    | `UpdateCheck`, `UpdateChannel`, `UpdateUrl` | проверка обновлений, stable/beta, свой адрес вместо GitHub |
    | `TelemetryEnabled`, `TelemetryEndpoint` | телеметрия (по умолчанию выключена) и сборщик компании |

  - **Где в коде.** Источник конфигурации из реестра и файла, подключённый последним (`Hosting`, рядом с
    `IUserSettings`); `IUserSettings.UpdateAsync` отказывает для заблокированного ключа; `ExtensionPaths.GetRoots`
    добавляет корни из политики (только для чтения — не `Dev`-зона); ADMX/ADML в `build/` и в MSI; свойства MSI в
    проекте установщика; раздел «Для администраторов» в `ONBOARDING.md` (ключи, ADMX, примеры GPO и Intune).
  - **Тесты.** Тир 1: порядок слоёв (по умолчанию / пользователь / HKCU / HKLM / файл), блокировка записи, ответ
    `managed_by_policy`, корни из политики только для чтения — реестр за интерфейсом, в тестах подставной.
  - **Объём.** 2–3 дня. Ветка `claude/enterprise-policy-phase1` решает другое — подписанный удалённый `policy.json`
    при «вступлении в организацию», обязательные расширения, защита от отката — и написана на коде 1.x. Не переносить
    сейчас; если понадобится централизованно раздавать расширения, добавить поверх этого слоя.
